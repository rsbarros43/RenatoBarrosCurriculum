Navegação

12. Troubleshooting

Nem tudo funciona de primeira. Este capítulo reúne os erros mais comuns que você vai encontrar ao longo do laboratório e como diagnosticá-los, com o mesmo raciocínio que se espera de alguém administrando OpenShift em produção: observar → isolar → corrigir.

Regra de ouro: quase todo problema no cluster começa com oc get events --sort-by=.lastTimestamp e oc describe no recurso suspeito.

Problemas comuns e como resolver

🛑 CRC não inicia

Sintoma: crc start falha ou trava em "Starting CRC VM".

Causa provável: virtualização desabilitada na BIOS/UEFI, ou libvirt/KVM mal configurado.

Solução: confirme suporte a virtualização, rode crc setup novamente e verifique se o usuário está nos grupos libvirt e kvm.

🛑 ImagePullBackOff

Sintoma: pod da aplicação fica preso sem subir.

Causa provável: a imagem ainda não foi publicada no registry interno (a pipeline não rodou) ou a tag está errada.

Solução: confirme se a PipelineRun terminou com Succeeded antes de esperar o Deployment funcionar.

🛑 CrashLoopBackOff

Sintoma: pod reinicia repetidamente.

Causa provável: erro na aplicação Flask — porta errada, dependência faltando, exceção na inicialização.

Solução: use oc logs deployment/flask-app para ver o stack trace real da aplicação.

🛑 Route retorna 503

Sintoma: a URL da aplicação responde "Application is not available".

Causa provável: nenhum pod está Ready, ou o Service aponta para o selector errado.

Solução: confira oc get pods e oc describe route flask-app para validar o roteamento.

🛑 InvalidWorkspaceBindings

Sintoma: a PipelineRun falha antes mesmo de começar a primeira Task.

Causa provável: a Pipeline exige um workspace obrigatório, mas o PipelineRun não enviou o binding correto.

Solução: revise o manual-pipelinerun.yaml e confirme que o nome do workspace bate com o definido na Pipeline.

🛑 Webhook não dispara a pipeline

Sintoma: você faz push no GitHub e nada acontece.

Causa provável: a URL do túnel ngrok expirou/mudou e o webhook no GitHub ainda aponta para a antiga.

Solução: gere uma nova URL com ngrok http 8080, atualize o webhook no GitHub e confirme que o EventListener está Running.

Comandos de diagnóstico

1. Ver logs da aplicação

oc logs deployment/flask-app
✓ Comando executado no simulador.

2. Inspecionar detalhes do pod

oc describe pod flask-app
✓ Comando executado no simulador.

3. Inspecionar a Route

oc describe route flask-app
✓ Comando executado no simulador.

4. Ver o histórico de eventos do namespace

oc get events --sort-by=.lastTimestamp
✓ Comando executado no simulador.
Dica de entrevista: descreva o ciclo de vida de um Pod (Pending → ContainerCreating → Running/CrashLoopBackOff) e explique como oc describe e oc logs se complementam no diagnóstico.
