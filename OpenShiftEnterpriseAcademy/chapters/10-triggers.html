Navegação

10. Tekton Triggers e GitHub Webhook

Agora vamos automatizar a execução da pipeline. A partir de um git push, o GitHub envia um webhook para o EventListener, que cria uma PipelineRun automaticamente.

O que é um webhook?

Normalmente, se um sistema quer saber se algo aconteceu em outro, ele precisa "ficar perguntando" de tempos em tempos (isso se chama polling). Um webhook inverte essa lógica: em vez de perguntar, o próprio GitHub avisa automaticamente — fazendo uma requisição HTTP para um endereço que você configurou — no exato momento em que algo acontece (como um push). É assim que a pipeline consegue rodar sozinha, sem ninguém clicando em nada: o GitHub "liga" para o nosso cluster assim que o código muda.

Fluxo: GitHub Push → Webhook → EventListener → TriggerBinding → TriggerTemplate → PipelineRun → Pipeline → Deploy.

Componentes de Trigger

EventListener: endpoint que recebe eventos externos.
TriggerBinding: extrai dados do payload do GitHub.
TriggerTemplate: cria o PipelineRun automático.
RBAC: permissões para o EventListener criar recursos.
Route ou ngrok: forma de expor o endpoint para o GitHub.

Sobre o oc port-forward

No laboratório final você vai ver o comando oc port-forward svc/el-github-eventlistener 8080:8080. Vale entender o que ele faz antes de chegar lá:

O que faz: cria um túnel temporário entre uma porta da sua máquina local e uma porta de um Service (ou Pod) dentro do cluster — sem precisar de Route nem Ingress.
Sintaxe: oc port-forward svc/nome-do-service PORTA_LOCAL:PORTA_DO_SERVICE. No nosso caso, 8080:8080 mapeia a porta 8080 local para a 8080 do EventListener.
Quando usar: ótimo para debug rápido e para testes locais (como abrir o túnel do ngrok em cima dele), mas não é uma solução permanente — a conexão cai se você fechar o terminal. Para exposição real e contínua, o certo é usar Route.

2. Aplicar TriggerBinding

oc apply -f tekton/triggers/triggerbinding.yaml
✓ Comando executado no simulador.

3. Aplicar TriggerTemplate

oc apply -f tekton/triggers/triggertemplate.yaml
✓ Comando executado no simulador.

4. Aplicar EventListener e Route

oc apply -f tekton/triggers/eventlistener.yaml oc apply -f tekton/triggers/route.yaml
✓ Comando executado no simulador.
✓ Comando executado no simulador.

5. Validar recursos

oc get eventlistener,triggerbinding,triggertemplate,route

Validação final

Depois de configurar o webhook no GitHub, um novo git push deve criar automaticamente uma PipelineRun no OpenShift.
oc get pipelinerun --sort-by=.metadata.creationTimestamp
