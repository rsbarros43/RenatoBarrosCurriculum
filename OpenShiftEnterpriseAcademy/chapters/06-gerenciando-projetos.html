Navegação

06. Gerenciando projetos no OpenShift

Em OpenShift, um projeto é a camada lógica usada para organizar aplicações, permissões, quotas, pipelines e objetos Kubernetes. Neste laboratório você vai criar e administrar o namespace principal do projeto: tekton-lab.

Fundamento: no Kubernetes chamamos de namespace. No OpenShift, o conceito aparece para o usuário como Project, com integrações de segurança, RBAC e console.

Objetivos do capítulo

Criar projeto: usar oc new-project para iniciar um ambiente isolado.
Alternar contexto: usar oc project para trabalhar no namespace correto.
Validar recursos: listar pods, services, routes e permissões do projeto.
Preparar CI/CD: deixar o projeto pronto para Flask, Tekton e Triggers.

Abreviações que você vai ver nos comandos

Ao longo do laboratório usamos os nomes abreviados dos objetos — é assim que profissionais de OpenShift/Kubernetes trabalham no dia a dia, para digitar menos:

po = pods — oc get po equivale a oc get pods.
svc = services — oc get svc.
deploy = deployments — oc get deploy.
rs = replicasets, rc = replicationcontrollers.
ns = namespaces (no OpenShift, equivalente a projects).
cm = configmaps, sa = serviceaccounts.
Para ver a lista completa de abreviações disponíveis no seu cluster, rode oc api-resources — ele mostra o nome completo, a abreviação e o Kind de cada tipo de objeto.

Laboratório guiado

1. Criar o projeto principal

oc new-project tekton-lab
✓ Comando executado no simulador.

2. Selecionar o projeto

oc project tekton-lab
✓ Comando executado no simulador.

3. Listar todos os projetos disponíveis

oc get projects
✓ Comando executado no simulador.

4. Validar recursos do projeto

oc get all
✓ Comando executado no simulador.

Boas práticas

Use nomes claros para projetos: dev, homolog, prod, tekton-lab. Em ambiente real, combine Project + RBAC + ResourceQuota + LimitRange.

Troubleshooting rápido

Forbidden: usuário sem permissão para criar projeto.
AlreadyExists: projeto já existe; use oc project tekton-lab.
No resources found: projeto criado, mas ainda sem aplicação.
