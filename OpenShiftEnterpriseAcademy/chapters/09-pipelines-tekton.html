09. Pipelines Tekton

Tekton é o mecanismo de CI/CD usado pelo OpenShift Pipelines. Nesta etapa vamos entender a pipeline que clona o repositório, constrói a imagem e realiza o deploy da aplicação Flask.

O que é CI/CD, em bom português?

CI (Continuous Integration / Integração Contínua) é o hábito de testar e validar o código automaticamente toda vez que alguém muda algo, em vez de só descobrir problemas depois. CD (Continuous Delivery/Deployment / Entrega Contínua) é levar essa mudança já validada até o ambiente rodando, de forma automática, sem alguém precisando copiar arquivos ou rodar comandos manualmente a cada nova versão. Juntas, essas duas práticas formam a pipeline: uma esteira de etapas encadeadas (clonar código → construir imagem → publicar → atualizar a aplicação) que roda sozinha a cada mudança.

Pipeline principal: clone-repository → build-and-push-image → deploy-to-openshift.

Componentes principais

Task: uma unidade reutilizável de trabalho — pense nela como "uma etapa" da esteira (ex: só clonar o repositório).
Pipeline: encadeamento de tasks, na ordem em que devem rodar.
PipelineRun: execução concreta de uma pipeline — cada vez que a esteira roda de verdade, gera um PipelineRun novo, com seu próprio histórico e log.
Workspace: área compartilhada entre tasks — por exemplo, a Task que clona o código e a Task que constrói a imagem precisam acessar os mesmos arquivos, e é o Workspace que permite isso.
Params: valores passados dinamicamente, como URL do repositório e branch.

Fluxo visual

1. Clonar repositório GitHub.
2. Construir imagem da aplicação Flask.
3. Publicar imagem no OpenShift Internal Registry.
4. Atualizar Deployment no namespace tekton-lab.

Laboratório guiado

1. Aplicar Tasks

oc apply -f tekton/tasks/clone-repository.yaml oc apply -f tekton/tasks/build-and-push-image.yaml oc apply -f tekton/tasks/deploy-to-openshift.yaml

Erro comum

InvalidWorkspaceBindings acontece quando a Pipeline exige um workspace obrigatório, mas o PipelineRun não recebeu o binding correto.
