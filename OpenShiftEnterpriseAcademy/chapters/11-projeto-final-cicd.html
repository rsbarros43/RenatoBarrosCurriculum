11. Projeto Final — Pipeline CI/CD completa

Este é o capítulo de fechamento prático. Aqui você não aprende conceito novo: você integra tudo o que foi visto do capítulo 6 ao 10 em um único fluxo, do jeito que aconteceria em um ambiente real de time de plataforma.

Fluxo completo: GitHub Push → Webhook → EventListener → TriggerBinding/TriggerTemplate → PipelineRun → Task clone → Task build (Buildah) → Registry interno → Task deploy → Deployment/Service/Route atualizados.

O que é o Buildah? É a ferramenta que a Task de build usa por baixo dos panos para transformar o Dockerfile em uma imagem de container de verdade — o "forno" que executa a receita que vimos no capítulo 8.

Visão geral da arquitetura final

Namespace: tekton-lab concentra aplicação, pipeline e triggers.
Aplicação: Flask exposta via Deployment, Service (ClusterIP) e Route (edge TLS).
Pipeline: 3 Tasks encadeadas (clone-repository, build-and-push-image, deploy-to-openshift).
Triggers: EventListener exposto via Route, recebendo webhook do GitHub através de um túnel ngrok (ambiente local).
Observabilidade: oc get pipelinerun e oc get events para confirmar que cada etapa terminou com sucesso.

Checklist antes de considerar o projeto pronto

1. Deployment, Service e Route da aplicação aplicados manualmente ao menos uma vez (baseline).
2. Tasks e Pipeline do Tekton aplicadas e visíveis com tkn pipeline list / oc get pipeline.
3. Execução manual da PipelineRun concluída com Succeeded.
4. RBAC, TriggerBinding, TriggerTemplate e EventListener aplicados no namespace.
5. Rota do EventListener exposta e alcançável via túnel (ngrok) para simular o webhook do GitHub.
6. Push simulado dispara uma nova PipelineRun automaticamente, sem intervenção manual.

Execução ponta a ponta (laboratório guiado)

1. Baseline da aplicação

oc apply -f openshift/deployment.yaml oc apply -f openshift/service.yaml oc apply -f openshift/route.yaml

2. Confirmar que a aplicação está de pé

oc get deployment,svc,route,pods
✓ Comando executado no simulador.

3. Publicar Tasks, Pipeline e disparar execução manual

oc apply -f tekton/tasks/clone-repository.yaml oc apply -f tekton/tasks/build-and-push-image.yaml oc apply -f tekton/tasks/deploy-to-openshift.yaml oc apply -f tekton/pipelines/pipeline.yaml oc create -f tekton/pipelineruns/manual-pipelinerun.yaml
✓ Comando executado no simulador.
✓ Comando executado no simulador.

4. Ligar os Triggers (RBAC + Binding + Template + EventListener + Route)

oc apply -f tekton/triggers/rbac.yaml oc apply -f tekton/triggers/triggerbinding.yaml oc apply -f tekton/triggers/triggertemplate.yaml oc apply -f tekton/triggers/eventlistener.yaml oc apply -f tekton/triggers/route.yaml
✓ Comando executado no simulador.

5. Expor o EventListener publicamente (simulação do webhook real)

oc port-forward svc/el-github-eventlistener 8080:8080 ngrok http 8080
✓ Comando executado no simulador.

6. Validar o disparo automático após o push

oc get pipelinerun --sort-by=.metadata.creationTimestamp
✓ Comando executado no simulador.

Critérios de aceite do projeto final

Considere o projeto concluído quando: a PipelineRun automática (disparada pelo webhook) aparece como Succeeded, o Deployment está 1/1 Available, a Route responde e o EventListener continua Running aguardando o próximo push.
Dica de entrevista: saiba explicar por que essa arquitetura é "GitOps-friendly" — o estado desejado vive em YAML versionado, e a pipeline só reflete o que já está declarado no repositório.
