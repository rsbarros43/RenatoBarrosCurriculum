Capítulo 02 — Pré-requisitos

Antes de instalar o OpenShift Local (CRC), prepare o host com virtualização, pacotes de rede, Git, curl, libvirt/KVM e NetworkManager. Este laboratório foi documentado usando Linux Mint, mas o CRC também roda oficialmente em macOS (incluindo Apple Silicon) e Windows — os pré-requisitos de virtualização e RAM são os mesmos, o que muda é a camada de virtualização usada por baixo (libvirt/KVM no Linux, HyperKit/vfkit no macOS, Hyper-V no Windows) e o instalador (binário extraído no Linux, instalador guiado no macOS/Windows).

Recomendação para estudo: 8 vCPU, 24 GB ou 32 GB de RAM no host e pelo menos 120 GB livres para trabalhar com conforto.

Checklist técnico

Virtualização: habilitada na BIOS/UEFI (Intel VT-x/AMD-V no Linux/Windows; nativa em Apple Silicon).
KVM/libvirt: camada de virtualização usada pelo CRC no Linux. No macOS e Windows o CRC usa seus próprios hypervisors integrados.
NetworkManager: necessário para gerenciar rede local do cluster (Linux).
Pull Secret: arquivo obtido no portal Red Hat para iniciar o cluster, igual em qualquer sistema operacional.

Ferramentas de linha de comando (CLI)

Durante o laboratório usamos o comando oc, mas vale entender a diferença para quem já conhece Kubernetes puro:

kubectl: CLI padrão do Kubernetes. Funciona no OpenShift porque o OpenShift é um Kubernetes por baixo — mas não entende objetos exclusivos do OpenShift, como Route ou DeploymentConfig.
oc: CLI do OpenShift. É um superset do kubectl: aceita os mesmos comandos (oc get pods funciona igual a kubectl get pods) e adiciona comandos próprios como oc new-project, oc new-app e oc expose.
Na prática: se você já tem o hábito com kubectl, pode continuar usando para a maioria dos comandos — mas para Routes, Projects e funcionalidades específicas do OpenShift, use oc.

Comandos base

sudo apt update sudo apt install -y qemu-kvm libvirt-daemon libvirt-daemon-system network-manager git wget curl sudo usermod -aG libvirt,kvm $USER
