História e objetivo do processo

O Oracle Universal Installer é normalmente usado em modo gráfico, exigindo que o DBA informe manualmente cada opção da instalação. Em ambientes profissionais, repetitivos ou automatizados, a instalação silent permite executar o mesmo fluxo com um arquivo de resposta ou com parâmetros informados diretamente na linha de comando.

Este laboratório mostra como registrar ou usar um response file, executar o runInstaller em modo silent, sobrescrever parâmetros pela linha de comando, instalar versões modernas como 18c/19c extraindo o software diretamente no ORACLE_HOME e aplicar patches durante a instalação.

A imagem ao lado representa a tela do OUI onde o DBA pode salvar um response file antes de iniciar a instalação. Ela é útil quando o DBA prefere montar a instalação pela interface e reaproveitar as escolhas em execuções silent.

Response Files

O que é?
Um response file é um arquivo de configuração que contém as respostas que seriam dadas manualmente durante o Oracle Universal Installer.
Quando usar?
Use para padronizar instalações, automatizar ambientes, repetir builds, criar laboratórios e reduzir erro humano.

Existem três formas principais de usar response files: editar o modelo fornecido pela mídia, usar o modelo e sobrescrever parâmetros na linha de comando, ou gerar um response file pela GUI do OUI.

1. Criar response file com -record em versões antigas
Antes do Oracle 11gR2 era possível iniciar o instalador com -record para gravar as opções escolhidas em um arquivo de resposta.
./runInstaller -record -destinationFile /tmp/10gR2.rsp
2. Abrir o OUI para salvar response file pela tela final
A partir do 11gR2, o parâmetro -record não é mais suportado. O OUI oferece a opção Save Response File na tela final antes da instalação.
./runInstaller

Using Response Files : Basic

A instalação silent é iniciada com -silent e -responseFile. O instalador lê o arquivo de resposta e executa sem solicitar entradas adicionais pela interface gráfica.
3. Silent installation normal
Executa uma instalação silent usando o response file informado.
./runInstaller -silent -responseFile /tmp/12cR2.rsp
4. Silent ignorando pré-requisitos e exibindo progresso
Útil para automação, porque ignora checks não críticos, aguarda o término do processo e mostra progresso na tela.
./runInstaller -ignoreSysPrereqs -ignorePrereq -waitforcompletion -showProgress -silent -responseFile /tmp/12cR2.rsp
5. Flags úteis do runInstaller
Lista de parâmetros comuns para instalações silent e scripts de automação.
-silent            : Executa em modo silent.
-responseFile      : Define o caminho do response file.
-ignoreSysPrereqs  : Ignora pré-requisitos do sistema.
-ignorePrereq      : Ignora pré-requisitos gerais.
-waitforcompletion : Aguarda o processo terminar, útil em scripts.
-invPtrLoc         : Especifica o oraInst.loc com detalhes do inventory.
-force             : Continua mesmo usando ORACLE_HOME não vazio.
-showProgress      : Mostra pontos de progresso durante a instalação.

Using Response Files : Command Line Overrides

Uma alternativa a editar manualmente o response file é usar o arquivo padrão da mídia e sobrescrever parâmetros diretamente na linha de comando. Isso deixa o processo mais fácil de versionar e adaptar.
6. Exemplo 12cR1 e versões anteriores
Exemplo usando o response file padrão e sobrescrevendo parâmetros como ORACLE_HOME, ORACLE_BASE, grupos e edição.
./runInstaller -ignoreSysPrereqs -ignorePrereq -waitforcompletion -showProgress -silent \
    -responseFile /tmp/database/response/db_install.rsp \
    oracle.install.option=INSTALL_DB_SWONLY \
    ORACLE_HOSTNAME=${ORACLE_HOSTNAME} \
    UNIX_GROUP_NAME=oinstall \
    INVENTORY_LOCATION=${ORA_INVENTORY} \
    SELECTED_LANGUAGES=en,en_GB \
    ORACLE_HOME=${ORACLE_HOME} \
    ORACLE_BASE=${ORACLE_BASE} \
    oracle.install.db.InstallEdition=EE \
    oracle.install.db.DBA_GROUP=dba \
    oracle.install.db.OPER_GROUP=dba \
    oracle.install.db.BACKUPDBA_GROUP=dba \
    oracle.install.db.DGDBA_GROUP=dba \
    oracle.install.db.KMDBA_GROUP=dba \
    SECURITY_UPDATES_VIA_MYORACLESUPPORT=false \
    DECLINE_SECURITY_UPDATES=true
7. Exemplo 12cR2
No 12cR2 os parâmetros dos grupos receberam prefixo OS, e o grupo OSRACDBA passou a ser obrigatório.

Using Response Files : 18c Onward - Unzip to ORACLE_HOME

A partir do Oracle 18c, o binário do banco é extraído diretamente dentro do ORACLE_HOME. Depois disso, o runInstaller é executado a partir do próprio home.
9. Extrair software no ORACLE_HOME
O arquivo ZIP do Oracle Database 18c/19c deve ser descompactado diretamente no ORACLE_HOME.
cd $ORACLE_HOME
unzip -oq /path/to/software/LINUX.X64_190000_db_home.zip
10. Instalação silent 18c/19c
Executa a instalação somente do software usando response file dentro do ORACLE_HOME e parâmetros inline.
./runInstaller -ignorePrereq -waitforcompletion -silent \
    -responseFile ${ORACLE_HOME}/install/response/db_install.rsp \
    oracle.install.option=INSTALL_DB_SWONLY \
    ORACLE_HOSTNAME=${ORACLE_HOSTNAME} \
    UNIX_GROUP_NAME=oinstall \
    INVENTORY_LOCATION=${ORA_INVENTORY} \
    SELECTED_LANGUAGES=en,en_GB \
    ORACLE_HOME=${ORACLE_HOME} \
    ORACLE_BASE=${ORACLE_BASE} \
    oracle.install.db.InstallEdition=EE \
    oracle.install.db.OSDBA_GROUP=dba \
    oracle.install.db.OSBACKUPDBA_GROUP=dba \
    oracle.install.db.OSDGDBA_GROUP=dba \
    oracle.install.db.OSKMDBA_GROUP=dba \
    oracle.install.db.OSRACDBA_GROUP=dba \
    SECURITY_UPDATES_VIA_MYORACLESUPPORT=false \
    DECLINE_SECURITY_UPDATES=true

Using Response Files : Patching Installation Media

O Oracle 18c introduziu a possibilidade de aplicar RU e one-off patches durante a instalação, antes da criação do banco. Isso evita instalar primeiro e patchar depois como etapas separadas.
11. Instalação com -applyRU
Aplica uma Release Update descompactada antes de concluir a instalação do ORACLE_HOME.
./runInstaller -ignorePrereq -waitforcompletion -silent \
    -applyRU /u01/software/10000000 \
    -responseFile ${ORACLE_HOME}/install/response/db_install.rsp \
    oracle.install.option=INSTALL_DB_SWONLY \
    ORACLE_HOSTNAME=${ORACLE_HOSTNAME} \
    UNIX_GROUP_NAME=oinstall \
    INVENTORY_LOCATION=${ORA_INVENTORY} \
    SELECTED_LANGUAGES=en,en_GB \
    ORACLE_HOME=${ORACLE_HOME} \
    ORACLE_BASE=${ORACLE_BASE} \
    oracle.install.db.InstallEdition=EE \
    oracle.install.db.OSDBA_GROUP=dba \
    oracle.install.db.OSBACKUPDBA_GROUP=dba \
    oracle.install.db.OSDGDBA_GROUP=dba \
    oracle.install.db.OSKMDBA_GROUP=dba \
    oracle.install.db.OSRACDBA_GROUP=dba \
    SECURITY_UPDATES_VIA_MYORACLESUPPORT=false \
    DECLINE_SECURITY_UPDATES=true
12. Instalação com -applyRU e -applyOneOffs
Permite combinar uma Release Update com múltiplos one-off patches separados por vírgula.
./runInstaller -ignorePrereq -waitforcompletion -silent \
    -applyRU /u01/software/10000000 \
    -applyOneOffs /u01/software/10000001,/u01/software/10000002 \
    -responseFile ${ORACLE_HOME}/install/response/db_install.rsp \
    oracle.install.option=INSTALL_DB_SWONLY \
    ORACLE_HOSTNAME=${ORACLE_HOSTNAME} \
    UNIX_GROUP_NAME=oinstall \
    INVENTORY_LOCATION=${ORA_INVENTORY} \
    SELECTED_LANGUAGES=en,en_GB \
    ORACLE_HOME=${ORACLE_HOME} \
    ORACLE_BASE=${ORACLE_BASE} \
    oracle.install.db.InstallEdition=EE \
    oracle.install.db.OSDBA_GROUP=dba \
    oracle.install.db.OSBACKUPDBA_GROUP=dba \
    oracle.install.db.OSDGDBA_GROUP=dba \
    oracle.install.db.OSKMDBA_GROUP=dba \
    oracle.install.db.OSRACDBA_GROUP=dba \
    SECURITY_UPDATES_VIA_MYORACLESUPPORT=false \
    DECLINE_SECURITY_UPDATES=true
13. Conceito equivalente para Grid Infrastructure
A mesma abordagem também está disponível para instalação do Grid Infrastructure.
./gridSetup.sh ... -silent -applyRU ${SOFTWARE_DIR}/10000000 ...
