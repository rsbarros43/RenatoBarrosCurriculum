História do processo

O Database Configuration Assistant, conhecido como DBCA, é a ferramenta da Oracle usada para criar, configurar, excluir e administrar bancos de dados. Normalmente ele pode ser utilizado pela interface gráfica, mas em ambientes corporativos, automações, laboratórios e pipelines, o modo silent permite executar a criação do banco sem interação manual.

Além da criação de bancos, o DBCA também pode modificar ou remover bancos, gerenciar templates e trabalhar com pluggable databases. Neste laboratório o foco é a criação e remoção de bancos em modo silencioso, usando response file ou parâmetros na linha de comando.

Response File

Conceito
O response file fornece todas as respostas que o DBCA pediria pela interface gráfica. O arquivo de exemplo pode ser encontrado em $ORACLE_HOME/assistants/dbca/dbca.rsp.
Oracle 19c
No Oracle 19c em diante, a operação deve ser informada junto com o response file. Para criação de banco, utilize -createDatabase.
1. Response file básico
O arquivo de resposta fornece ao DBCA todas as respostas que normalmente seriam preenchidas na interface gráfica. O exemplo padrão fica em $ORACLE_HOME/assistants/dbca/dbca.rsp.
dbca -silent -responseFile ./dbca.rsp
2. Response file no Oracle 19c
A partir do Oracle 19c, além do response file, a operação precisa ser informada explicitamente. Para criar banco, use -createDatabase junto com -silent e -responseFile.
dbca -createDatabase -silent -responseFile ./dbca.rsp
3. Seções importantes do dbca.rsp
O arquivo dbca.rsp é grande porque suporta várias ações. Para criar banco, foque na seção [CREATEDATABASE] e ignore as demais seções quando não forem necessárias.
[CREATEDATABASE]
[createTemplateFromDB]
[createCloneTemplate]
[DELETEDATABASE]
[generateScripts]
[CONFIGUREDATABASE]
[ADDINSTANCE]
[DELETEINSTANCE]
[CREATEPLUGGABLEDATABASE]
[UNPLUGDATABASE]
[DELETEPLUGGABLEDATABASE]
[CONFIGUREPLUGGABLEDATABASE]

Command Line

A abordagem por linha de comando é mais clara em laboratórios porque mostra todos os parâmetros relevantes, como SID, CDB, PDB, charset, memória, destino dos datafiles e configuração do Enterprise Manager.
4. Criar CDB/PDB por linha de comando
Alternativa mais clara para laboratórios: informar todos os parâmetros diretamente na linha de comando. Este exemplo cria o CDB cdb3 com a PDB pdb3, charset AL32UTF8, memória de 1536 MB e arquivos em filesystem.
dbca -silent -createDatabase \
 -templateName General_Purpose.dbc \
 -gdbname cdb3 -sid cdb3 -responseFile NO_VALUE \
 -characterSet AL32UTF8 \
 -sysPassword OraPasswd1 \
 -systemPassword OraPasswd1 \
 -createAsContainerDatabase true \
 -numberOfPDBs 1 \
 -pdbName pdb3 \
 -pdbAdminPassword OraPasswd1 \
 -databaseType MULTIPURPOSE \
 -memoryMgmtType auto_sga \
 -totalMemory 1536 \
 -storageType FS \
 -datafileDestination "/u01/app/oracle/oradata/" \
 -redoLogFileSize 50 \
 -emConfiguration NONE \
 -ignorePreReqs

Delete Database

O DBCA em silent mode também remove bancos. Antes de usar em ambientes reais, valide backup, dependências, listener, arquivos de rede e diretórios físicos.
5. Excluir o banco cdb2
O DBCA também permite remover bancos em silent mode. O comando conecta como SYS, atualiza arquivos de rede e remove instância/datafiles.
dbca -silent -deleteDatabase -sourceDB cdb2 -sysDBAUserName sys -sysDBAPassword OraPasswd1
6. Excluir o banco cdb3
Mesmo processo para o banco cdb3 criado via linha de comando. Em ambiente real, valide backup, dependências e diretórios antes da remoção.
dbca -silent -deleteDatabase -sourceDB cdb3 -sysDBAUserName sys -sysDBAPassword OraPasswd1

Oracle Managed Files no DBCA

Com -useOMF true, o Oracle gerencia automaticamente nomes e localização lógica dos arquivos, reduzindo erros de nomenclatura e simplificando a administração.
7. Criar banco usando OMF
No Oracle 18c/19c, a flag -useOMF true habilita Oracle Managed Files durante a criação, simplificando o gerenciamento de datafiles, controlfiles e redo logs.
dbca -silent -createDatabase \
 -templateName General_Purpose.dbc \
 -gdbname cdb3 -sid cdb3 -responseFile NO_VALUE \
 -characterSet AL32UTF8 \
 -sysPassword OraPasswd1 \
 -systemPassword OraPasswd1 \
 -createAsContainerDatabase true \
 -numberOfPDBs 1 \
 -pdbName pdb3 \
 -pdbAdminPassword OraPasswd1 \
 -databaseType MULTIPURPOSE \
 -memoryMgmtType auto_sga \
 -totalMemory 1536 \
 -storageType FS \
 -datafileDestination "/u01/app/oracle/oradata/" \
 -useOMF true \
 -redoLogFileSize 50 \
 -emConfiguration NONE \
 -ignorePreReqs

Validação pós-criação

Após a criação do banco, use SQL*Plus para validar nome do banco, modo de abertura, PDBs e status da instância.
8. Validar banco criado
Depois da criação, valide conexão, CDB/PDB, versão e status da instância usando SQL*Plus.
sqlplus / as sysdba
select name, open_mode from v$database;
show pdbs
select instance_name, status from v$instance;
